# 实验分析

实验分析基于实验决策记录和主执行记录，比较各分组的流量分配、运行情况和预测结果分布。

本教程介绍如何通过命令行和管理控制台查看实验分析结果。开始前，请确认当前账户具备 `experiment.read` [权限](../reference/states-permissions.md#权限全集)。

## 通过命令行查看

使用以下命令查看实验分析结果：

```bash
datamind experiment analyze <experiment_id>
```

其中，`<experiment_id>` 为实验的 ID，可通过以下命令查询：

```bash
datamind experiment list
```

默认以对照组为比较基准，也可通过 `--baseline-variant-id` 指定当前实验中的其他分组：

```bash
datamind experiment analyze <experiment_id> --baseline-variant-id <variant_id>
```

使用 `--format json` 以 JSON 格式输出分析结果，便于保存或进一步处理：

```bash
datamind experiment analyze <experiment_id> --format json
```

## 通过控制台查看

在管理控制台打开实验详情，**实验分析**区域展示请求数、主体数、成功率和平均耗时。点击**查看全部**按钮，查看完整分析结果：

- **指标比较**：展示各组指标，以及相对基准组的绝对差异和相对变化；有分类预测结果时，还会展示分类标签分布。
- **分组流量**：展示各组的决策占比、请求数和主体数。
- **执行状态**：展示各组的主执行数及各状态计数。

在**比较基准**下拉列表中选择基准组，点击**刷新**按钮更新分析结果。

## 指标口径

实验分析根据实验决策记录统计请求量，并通过主执行记录计算成功率、平均耗时，以及概率、评分的均值和范围等指标。 统计范围仅限参与实验的请求，不包含影子执行；同一主体的多次请求分别计数。

以下指标按实验分组统计：

| 指标         | 字段                  | 含义                                                                     |
|--------------|-----------------------|--------------------------------------------------------------------------|
| 决策记录数   | `total_count`         | 分组内的决策记录数                                                       |
| 主体数       | `subject_count`       | 分组内的主体数，按主体类型和主体标识的组合去重，缺失主体标识的记录不计入 |
| 分配记录数   | `assignment_count`    | 分组内的分配记录数，按分配 ID 去重                                       |
| 流量比例     | `traffic_ratio`       | 该分组的决策记录数占整个实验决策记录总数的比例                           |
| 执行数       | `execution_count`     | 主执行记录数                                                             |
| 已结束执行数 | `completed_count`     | 状态为成功、失败、超时或取消的执行记录数                                 |
| 成功率       | `success_rate`        | 成功的执行记录数占已结束执行记录总数的比例                               |
| 平均耗时     | `average_latency_ms`  | 已结束执行记录的平均耗时，单位为毫秒                                     |
| 平均概率     | `average_probability` | 成功执行记录中预测概率的平均值                                           |
| 最小概率     | `minimum_probability` | 成功执行记录中预测概率的最小值                                           |
| 最大概率     | `maximum_probability` | 成功执行记录中预测概率的最大值                                           |
| 平均评分     | `average_score`       | 成功执行记录中评分的平均值                                               |
| 最小评分     | `minimum_score`       | 成功执行记录中评分的最小值                                               |
| 最大评分     | `maximum_score`       | 成功执行记录中评分的最大值                                               |
| 预测决策分布 | `decision_counts`     | 实验决策记录中各决策结果的数量                                           |
| 分类标签分布 | `prediction_counts`   | 成功执行记录中各分类标签的数量                                           |

例如，某实验的 100 次请求均已执行结束并记录耗时，各组统计结果如下：

| 分组   | 决策记录数 | 成功执行数 | 耗时总和  |
|--------|------------|------------|-----------|
| 对照组 | 75         | 70         | 1500 毫秒 |
| 实验组 | 25         | 20         | 750 毫秒  |

对应的指标为：

- **流量比例**：对照组为 `75 / 100 = 75%`，实验组为 `25 / 100 = 25%`。
- **成功率**：对照组为 `70 / 75 ≈ 93.33%`，实验组为 `20 / 25 = 80%`。
- **平均耗时**：对照组为 `1500 / 75 = 20` 毫秒，实验组为 `750 / 25 = 30` 毫秒。

> **统计说明**
>
> 流量比例反映参与实验的请求在各分组间的实际分布，不等同于实验配置中的曝光比例。曝光比例用于哈希分配时的主体筛选，详见[实验分配](assignment.md)。流量统计以实验决策记录为准，未执行或执行未结束的请求不纳入成功率和平均耗时统计。
>
> 主体数按分组分别去重。管理控制台中的**分组主体**为各组主体数之和，同一主体出现在多个分组时会重复计数。
>
> 计算平均耗时、平均概率和平均评分，以及概率和评分的最小值、最大值时，忽略缺失值、布尔值和非有限数值；无有效数值时，相应指标返回 `null`。分组内的请求均未执行或执行未结束时，成功率返回 `null`。

## 分组比较

分组比较以对照组或指定的分组为基准，比较成功率、平均耗时、平均概率和平均评分。基准组与当前组都有相应的有效指标值时，才计算差异：

| 差异类型 | 字段            | 计算方式                                         |
|----------|-----------------|--------------------------------------------------|
| 绝对差异 | `absolute_lift` | 当前组指标值减去基准组指标值                     |
| 相对变化 | `relative_lift` | 绝对差异除以基准组指标值；基准值为 0 时为 `null` |

控制台以百分点（`pp`）显示成功率和平均概率的绝对差异，以百分比（`%`）显示各项指标的相对变化。

> **注意**
>
> 实验分析仅展示运行指标及分组差异，不对实际业务效果或差异的统计显著性作出结论。

## 生命周期

实验状态控制后续请求是否参与实验，不影响已有记录的分析。各操作对应的状态变化如下：

| 操作       | 状态变化                                                              | 效果                                                                                        |
|------------|-----------------------------------------------------------------------|---------------------------------------------------------------------------------------------|
| `start`    | `draft` / `paused` → `running`                                        | 启动 / 恢复实验，校验分组、关联部署和分配配置，并确认同一模型在当前环境下无其他运行中的实验 |
| `pause`    | `running` → `paused`                                                  | 暂停实验，后续请求走普通路由，未命中时回退默认部署                                          |
| `stop`     | `running` / `paused` → `stopped`                                      | 停止实验，不可重新启动                                                                      |
| `complete` | `running` / `paused` → `completed`                                    | 完成实验，不可重新启动                                                                      |
| `archive`  | `draft` / `running` / `paused` / `stopped` / `completed` → `archived` | 归档实验，不可再变更状态                                                                    |

启动实验，或恢复已暂停的实验：

```bash
datamind experiment start <experiment_id>
```

暂停实验：

```bash
datamind experiment pause <experiment_id>
```

完成实验：

```bash
datamind experiment complete <experiment_id>
```

结束实验不会自动切换模型版本。如需发布候选版本，请参阅[全量发布](../deployment/full.md#版本切换)。完整实验流程见[A/B 测试](index.md)。

## 配置修改与删除

**修改配置**

实验处于草稿状态（`draft`）时，可设置分配策略、曝光比例、主体字段、生效时间和实验分组。

实验暂停后不会恢复为草稿，配置修改仍受状态限制：

- 管理控制台仅允许编辑草稿实验。
- 实验处于暂停状态（`paused`）时，仅可通过 `datamind experiment update` 修改说明（`description`）和结束时间（`effective_to`）。
- 运行中、已停止、已完成或已归档的实验不允许修改。

**删除与恢复**

删除和恢复操作需要 `experiment.delete` 权限。实验采用逻辑删除：

- 仅草稿和已归档的实验允许删除，其他状态的实验需先归档。
- 删除实验时，同时删除其分组；恢复实验时，同时恢复随该实验一并删除的分组。
- 恢复后保留删除前的状态，已归档的实验不会重新启动。

状态限制和权限要求请参阅[状态与权限](../reference/states-permissions.md)。命令参数请参阅[实验管理](../cli/experiment.md)和[实验分组](../cli/variant.md)。
