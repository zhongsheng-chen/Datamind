# 模型与版本

一个模型可以包含多个版本；每个版本对应一次可独立发布的交付，模型文件则是预测服务实际加载的内容。部署引用一个版本，将其发布到指定环境。

## 模型交付流程

```text
训练模型 → 注册版本 → 创建部署 → 接入流量 → 执行预测 → 观测结果
```

模型名称标识预测能力，版本标识具体交付，部署指定版本的运行环境和发布方式。路由与实验决定请求使用哪个部署，运行实例记录各预测服务 Worker 的加载状态。

平台保存请求、决策和执行记录，用于追踪实际使用的部署与版本。实验分组的流量、运行情况与预测分布见[实验分析](../experiments/analysis.md)。

## 资源关系

| 资源 | 职责 | 关系 |
| --- | --- | --- |
| 模型（`Model`） | 保存名称、框架、模型类型和任务类型 | 包含多个版本 |
| 版本（`Version`） | 标识一次可独立发布、比较和回退的交付 | 属于一个模型，指向当前模型文件 |
| 模型文件（`Artifact`） | 保存文件位置、摘要和修订信息 | 属于一个版本，保留文件更新历史 |
| 部署（`Deployment`） | 指定环境、发布方式、角色与状态 | 引用一个版本 |

例如，`scorecard-demo` 的 `1.0.0` 和 `1.1.0` 是同一评分卡模型的两个版本。两者可分别部署，调用方通过模型名称发起请求，由路由或实验选择实际执行的部署。文件名用于保存模型，版本号用于标识交付。

## 模型身份

模型名称是注册后续版本、创建部署和发起预测时使用的稳定标识。框架、模型类型和任务类型在模型创建后固定，新版本沿用这些属性。

同一预测能力的更新使用新版本。更换框架、算法类型或任务类型时，应注册新的模型。文件改名或移动不会产生新的模型身份。

## 版本与文件修订

业务版本号区分可独立发布的交付；文件修订号区分同一版本先后保存的内容。

首次注册创建文件修订 `1`。重复提交相同内容返回已有记录，修订号保持不变。发布前修正文件时，可以在满足注册约束的情况下使用 `--force` 保存新修订，版本指向新的当前文件。

`artifact_revision` 用于识别文件更新，部署仍通过版本选择执行内容。已发布模型的更新应使用新业务版本，以保留发布、回退和历史预测的对应关系。强制重新注册的条件与命令见[模型管理](../models/index.md)。

## 版本与部署

一个版本可以部署到不同环境，也可以用于不同发布阶段。创建部署记录发布配置，启用部署后由预测服务协调模型加载。各 Worker 的实际状态由运行实例（`Runtime`）记录。

路由（`Routing`）和实验分组（`Variant`）引用部署。调整流量配置改变请求去向，模型和版本的身份保持不变。部署状态与加载状态的区别见[部署与运行](../deployment/index.md)，请求选择规则见[流量分配与决策优先级](../routing/index.md)。

## 生命周期

停用用于暂时停止使用，弃用和归档用于退出发布周期。逻辑删除保留数据库记录和模型文件；永久清理删除物理文件，已清理的文件无法通过恢复操作找回。

下线按依赖关系进行：先结束实验并移除路由，再停用部署并等待卸载，随后删除部署，最后处理版本和模型。完整状态转换见[状态与权限](../reference/states-permissions.md)，操作入口见[模型管理](../models/index.md)。
