# 资源

模型从注册到运行，由一组相互关联的资源管理，涵盖模型与版本、模型文件及其修订，以及部署和运行实例。其中，模型是版本管理与发布的基础。一个模型可包含多个版本，每个版本关联相应的模型文件。部署引用指定版本，将其发布到运行环境，由预测服务加载模型文件并执行预测。

## 资源关系

| 资源                   | 职责                                             | 关系                                           |
|------------------------|--------------------------------------------------|------------------------------------------------|
| 模型（`Model`）        | 标识预测能力，保存名称、框架、模型类型和任务类型 | 包含多个版本                                   |
| 版本（`Version`）      | 管理可独立发布、比较和回退的模型版本             | 属于一个模型，引用当前文件修订                 |
| 文件修订（`Artifact`） | 记录一次模型文件修订的存储位置、摘要和清理状态   | 属于一个版本；一个版本可保留多个修订           |
| 部署（`Deployment`）   | 指定版本的运行环境、发布方式、角色与状态         | 引用一个版本                                   |
| 运行实例（`Runtime`）  | 记录模型的加载状态、心跳和错误                   | 对应一个部署在一个预测服务 Worker 中的运行状态 |

例如，`scorecard-demo` 的 `1.0.0` 和 `1.1.0` 是同一模型的两个版本，可分别创建部署。预测请求可显式指定部署，也可由系统选择；文件名、版本号和部署分别承担文件识别、版本管理和发布配置的职责。

## 工作流程

模型从训练到提供预测服务，主要经过以下阶段：

```mermaid
flowchart LR
    A[训练模型] --> B[注册版本]
    B --> C[创建部署]
    C --> D[接入流量]
    D --> E[执行预测]
    E --> F[观测结果]
```

模型训练完成后，先注册模型版本，再创建部署并接入流量。预测服务加载部署对应的模型，处理预测请求并返回结果。通过请求、决策和执行记录，可以追踪每次预测所使用的版本，并观测模型的实际表现。

## 模型身份

模型名称是模型的稳定标识，用于版本注册、部署创建和预测调用。模型迭代应通过新版本管理，并保持框架、模型类型和任务类型一致；更换其中任一项时，应注册新模型。模型文件的重命名或移动不改变模型身份。

## 版本与文件修订

版本号区分模型的发布版本，文件修订记录同一版本内的文件变化。每条 `Artifact` 记录对应一次修订。版本引用当前修订，历史修订仍予以保留。

首次注册创建修订 `1`。再次注册同一版本时，模型须未归档、版本须未逻辑删除，具体处理方式如下：

- **框架和文件内容不变**：返回已有记录，不增加修订号，无论是否指定 `--force`。文件名和路径的变化不影响判断。
- **框架或文件内容变化**：仅当版本处于 `inactive` 状态且所有关联部署均已删除时，才可通过 `--force` 更新文件。更新会创建新修订并将其设为当前修订，原修订继续保留。

> **提示**
>
> 对于已发布的模型，建议[注册新版本](../models/index.md#注册新版本)进行迭代，便于版本回退和历史预测结果追溯。具体操作请参阅[模型管理](../models/index.md)。

## 版本与部署

部署以版本为基础，将模型发布到不同环境或发布阶段，并使用该版本当前的文件修订加载模型。

- **部署与加载**：创建和启用部署均要求模型及版本已激活。部署启用后，各预测服务 Worker 异步加载模型，实际状态由运行实例记录。详细说明请参阅[部署与运行](../deployment/index.md)。
- **流量分配**：路由和实验分组引用部署，决定请求的预测目标。调整流量不会改变模型与版本的身份，具体过程请参阅[流量分配与决策优先级](../routing/index.md)。

## 生命周期

- **状态管理**：停用后可重新激活；弃用后不可再激活，但可归档；归档后生命周期结束。
- **删除与清理**：逻辑删除保留资源记录和模型文件，符合条件时可以恢复。永久删除会清除模型文件，当前修订的文件一旦开始清理，版本便无法恢复。

状态转换与约束请参阅[状态与权限](../reference/states-permissions.md)，具体操作请参阅[模型管理](../models/index.md)。
