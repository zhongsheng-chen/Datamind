# 模型与版本

一个模型可以包含多个版本，每个版本关联自己的制品，也可以部署到不同环境。以下资源共同描述模型从注册到运行的过程。

| 资源 | 作用 | 关系 |
| --- | --- | --- |
| 模型（`Model`） | 保存名称、框架和任务类型 | 包含多个版本 |
| 版本（`Version`） | 标识一次业务版本 | 指向当前制品修订 |
| 制品（`Artifact`） | 保存模型文件与摘要 | 属于一个版本 |
| 部署（`Deployment`） | 指定发布环境、方式和角色 | 使用一个版本 |
| 路由（`Routing`） | 设置比例、条件和生效时间 | 指向一个部署 |
| 运行实例（`Runtime`） | 记录节点加载与运行状态 | 对应部署的实际执行 |
| 实验 / 分组（`Experiment` / `Variant`） | 比较不同版本的表现 | 每个分组绑定一个部署 |

## 从注册到运行

注册生成模型、版本和制品记录。激活后可以创建部署，启用部署后预测服务开始加载模型。路由则决定请求如何分配到这些部署。

部署状态表示管理配置，运行实例表示节点实际状态。部署已经启用时，模型可能仍在加载，也可能加载失败，因此发布后需要分别检查两者。

## 版本与修订

业务版本号用于发布和比较，例如 1.0.0 与 1.1.0。制品修订号记录同一版本中的文件变化，例如 `revision` 1 与 `revision` 2。

相同制品重复注册会复用已有记录。替换同一版本的制品有额外限制，已部署版本应通过新业务版本交付。详细规则见[模型与版本](../models/index.md)。

## 下线与删除

暂时下线使用停用，正式退出使用弃用或归档。逻辑删除保留记录和制品，永久清理才删除物理文件。恢复已删除资源仍受生命周期与关联资源约束。

操作时先处理流量，再停用部署并等待卸载，最后处理版本和制品。完整转换见[状态与权限](../reference/states-permissions.md)。
