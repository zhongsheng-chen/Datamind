# 架构

Datamind 将模型管理的控制面与实际执行预测的运行面分开。

## 模型交付链路

核心资源关系可以简化为：

```text
Model
  └─ Version
      └─ Artifact
          └─ Deployment
              └─ Routing
                  └─ Runtime
```

## 控制面

控制面负责模型服务的配置和生命周期管理，主要包括：

- **CLI / Console**：管理模型、部署、路由、实验、用户和角色。
- **Services**：处理资源生命周期和业务约束。
- **Database**：使用 PostgreSQL 持久化平台状态。
- **Auth / Audit**：提供认证、权限控制和操作追踪。

## 运行面

运行面负责真正的模型加载与预测执行，主要包括：

- **Runtime**：执行路由、模型装载和在线预测。
- **Task Queue**：协调批量预测、影子预测等异步任务。
- **Storage**：保存本地或 MinIO 中的模型制品。

## 设计边界

Datamind 管理的是模型服务和预测执行。

它负责回答：

```text
给定输入，模型输出什么结果？
```

它不负责决定：

```text
是否审批？
授信额度是多少？
业务策略如何组合？
```

这些决策应由上层业务系统或决策系统负责。
