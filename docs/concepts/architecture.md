# 架构

Datamind 由管理服务和预测服务组成，共享数据库与模型制品。管理服务配置模型如何发布，预测服务根据这些配置选择版本并执行预测。

## 管理服务

CLI 和 Console 提供模型、部署、路由、实验及账户管理入口。管理操作经过共享服务校验，再将资源状态保存到 PostgreSQL。认证与权限控制调用范围，审计记录操作过程。

## 预测服务

Runtime 接收在线请求，选择部署并加载对应模型。批量和影子预测通过 Redis 消息队列交给任务 Worker 执行，结果写回数据库，供调用方与 Console 查询。

模型制品存放在本地目录或 MinIO。使用多个 Runtime 或 Worker 时，每个进程都需要访问对应制品，并安装匹配的模型框架。

## 一次模型发布

发布从注册制品开始：模型保存名称和任务信息，版本指向具体制品，部署指定版本与发布方式，路由分配请求流量。Runtime 根据部署目标加载模型，生成预测与执行记录。

```text
模型 → 版本 → 制品
        ↓
       部署 ← 路由
        ↓
    Runtime / 任务 Worker
        ↓
    预测结果与执行记录
```

模型激活、部署启用和实际加载是三个步骤。管理操作成功后，还要检查运行状态并发起预测，确认服务已经可用。各资源的职责见[资源与生命周期](resources.md)。

## 接入业务系统

业务系统提交模型特征，接收类别、概率或评分，再结合自身规则处理审批、额度等业务流程。需要比较后验表现时，将业务结果作为 Outcome 回流到平台，用于实验分析。
