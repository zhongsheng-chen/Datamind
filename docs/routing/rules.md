# 路由规则

路由规则用于判断请求是否符合路由的匹配条件。未设置规则或规则为空时，匹配所有请求。匹配后是否选中部署，还取决于流量比例。具体分配过程请参阅[流量分配与决策优先级](index.md)。

> **注意**
>
> 规则不匹配时，路由不参与本次分配，并不意味着请求会被拒绝。普通路由还可能选中其他部署，或回退到默认部署；影子路由不匹配时，不向其绑定的部署复制请求。

## 配置规则

规则以 JSON 文件保存，创建或更新路由时通过 `--rules-file` 加载。

### 编写规则

例如，以下规则匹配年龄不低于 18 岁、年收入在 50000 至 200000 之间的请求。将其保存为 `routing-rules.json`：

```json
{
  "match": "all",
  "conditions": [
    {"field": "features.age", "op": "gte", "value": 18},
    {"field": "features.annual_income", "op": "between", "value": [50000, 200000]}
  ]
}
```

规则仅用于匹配请求，不会修改模型输入。

### 创建路由

创建路由时，指定绑定的部署并加载规则文件：

```bash
datamind route create <deployment_id> \
  --name example-route \
  --traffic-ratio 1.0 \
  --rules-file routing-rules.json
```

### 更新路由

已有路由可直接加载规则文件，替换原有规则：

```bash
datamind route update <routing_id> \
  --rules-file routing-rules.json
```

## 字段与条件

每条条件由 `field`、`op` 和 `value` 组成，分别表示匹配字段、运算符和比较值。检查字段是否存在或是否为 `null` 时，可以省略 `value`。

### 字段取值

路由规则根据请求载荷中 `features` 对象的字段值进行匹配。以年收入为例，以下写法均可引用其中的 `annual_income`：

- `annual_income`
- `features.annual_income`
- `request.features.annual_income`

嵌套字段使用点号分隔，例如 `customer.age`；数组元素使用从 0 开始的下标，例如 `orders.0.amount`。

例如，请求载荷中的 `features` 对象如下：

```json
{
  "features": {
    "customer": {"age": 35},
    "orders": [{"amount": 1000}]
  }
}
```

其中，`customer.age` 取值为 `35`，`orders.0.amount` 取值为 `1000`。

### 条件组合

`match` 决定如何组合 `conditions` 中的条件：

| 取值  | 匹配方式                       |
|-------|--------------------------------|
| `all` | 所有条件均成立，默认使用此方式 |
| `any` | 至少一个条件成立               |

为单条条件设置 `"negate": true`，可以将该条件的结果取反。例如：

```json
{
  "match": "all",
  "conditions": [
    {
      "field": "age",
      "op": "gte",
      "value": 18,
      "negate": true
    }
  ]
}
```

原条件判断年龄是否不低于 18 岁，设置 `negate` 后结果取反：年龄为 20 时不匹配，年龄为 16 时匹配。若 `age` 缺失，原条件不匹配，取反后也会匹配。

> **注意**
>
> 空规则和空条件列表均匹配所有请求，即使 `match` 为 `any`。需要限制请求范围时，应提供具体条件。

### 运算符

**比较与范围**

| 运算符    | 含义                         | 取值要求         |
|-----------|------------------------------|------------------|
| `eq`      | 等于指定值                   | 任意 JSON 值     |
| `ne`      | 不等于指定值                 | 任意 JSON 值     |
| `gt`      | 大于指定值                   | 数值或数字字符串 |
| `gte`     | 大于等于指定值               | 数值或数字字符串 |
| `lt`      | 小于指定值                   | 数值或数字字符串 |
| `lte`     | 小于等于指定值               | 数值或数字字符串 |
| `between` | 位于指定范围内，包含两端边界 | `[下限, 上限]`   |

> **注意**
>
> `gt`、`gte`、`lt`、`lte` 和 `between` 支持数值和数字字符串，数字字符串会先转换为数值。任一参与比较的值为布尔值或无法转换为数值时，匹配结果为 `false`，不会抛出异常。

**集合与字符串**

| 运算符         | 含义                                                   | 取值要求         |
|----------------|--------------------------------------------------------|------------------|
| `in`           | 值属于指定集合；字段值为数组时，至少一个元素属于该集合 | 数组             |
| `not_in`       | 值不属于指定集合；字段值为数组时，没有元素属于该集合   | 数组             |
| `contains`     | 包含指定子串、数组元素或对象键                         | 子串、元素或键   |
| `not_contains` | 不包含指定子串、数组元素或对象键                       | 子串、元素或键   |
| `startswith`   | 以指定内容开头                                         | 字符串           |
| `endswith`     | 以指定内容结尾                                         | 字符串           |
| `regex`        | 字符串中存在符合正则表达式的内容                       | 正则表达式字符串 |

> **注意**
>
> `eq`、`ne`、`in` 和 `not_in` 支持数值与数字字符串比较，数字字符串会先转换为数值。例如，`"18"` 和 `18` 视为相等。
>
> `startswith`、`endswith` 和 `regex` 匹配前，会将字段值与 `value` 转为字符串。正则表达式默认不要求匹配整个字符串；需要完整匹配时，可使用 `^` 和 `$` 限定边界。

**存在与空值**

| 运算符     | 含义                | 取值要求 |
|------------|---------------------|----------|
| `exists`   | 字段存在且非 `null` | 可省略   |
| `missing`  | 字段缺失或为 `null` | 可省略   |
| `is_null`  | 字段值为 `null`     | 可省略   |
| `not_null` | 字段存在且非 `null` | 可省略   |

未设置 `value` 和 `negate` 时，字段缺失与空值的匹配结果如下：

| 字段情况    | `exists` | `missing` | `is_null` | `not_null` |
|-------------|----------|-----------|-----------|------------|
| 字段缺失    | 不匹配   | 匹配      | 不匹配    | 不匹配     |
| 值为 `null` | 不匹配   | 匹配      | 匹配      | 不匹配     |
| 值非 `null` | 匹配     | 不匹配    | 不匹配    | 匹配       |

例如，检查 `age` 是否存在且非 `null`，可以写成：

```json
{
  "match": "all",
  "conditions": [
    {
      "field": "age",
      "op": "exists"
    }
  ]
}
```

将 `op` 换为其他运算符时，匹配结果如下。示例中的 JSON 表示 `features` 对象，均未设置 `value` 和 `negate`。

| 输入示例        | 匹配的运算符         | 原因                                    |
|-----------------|----------------------|-----------------------------------------|
| `{}`            | `missing`            | 未提供 `age`；字段缺失不等于值为 `null` |
| `{"age": null}` | `missing`、`is_null` | `age` 存在，但值为 `null`               |
| `{"age": 18}`   | `exists`、`not_null` | `age` 存在，且值非 `null`               |

> **注意**
>
> 这些运算符只检查字段是否存在、值是否为 `null`，不判断值是否符合业务要求。`0`、`false`、`""`、`[]` 和 `{}` 都是非 `null` 的值；例如，`{"age": ""}` 仍会匹配 `exists` 和 `not_null`。
>
> 对 `exists` 或 `missing` 设置 `"value": false`，会反转其检查结果。`is_null` 和 `not_null` 不使用 `value`。
>
> 字段缺失时，其他运算符均不匹配，包括 `ne`、`not_in` 和 `not_contains`。若设置 `"negate": true`，则在此基础上取反。

### 规则校验

加载规则时会检查配置，以下情况会被拒绝：

- 使用不支持的运算符，或缺少必填字段。
- `in`、`not_in` 的 `value` 不是数组。
- `between` 的 `value` 不是包含两个值的数组。

> **注意**
>
> 正则表达式在匹配请求时执行，不在加载规则时校验。表达式无效时返回不匹配，不会抛出异常；若设置了 `negate`，结果仍会取反。

### 兼容元数据

为兼容已有配置，规则 JSON 对象的顶层支持 `bucket_key`、`bucket_range`、`customer_id`、`hash_salt`、`salt`、`description`、`note` 和 `version`。这些元数据不参与条件匹配；规则中没有条件时，匹配所有请求。

以客户号 `C001` 为例，同一个字段写在不同位置，作用也不同。

**写入 `conditions`：筛选请求**

```json
{
  "match": "all",
  "conditions": [
    {
      "field": "customer_id",
      "op": "eq",
      "value": "C001"
    }
  ]
}
```

仅匹配客户号为 `C001` 的请求。

**写在顶层：记录元数据**

```json
{
  "customer_id": "C001"
}
```

不按客户号筛选，匹配所有请求。

> **注意**
>
> `bucket_key`、`bucket_range` 等兼容元数据不会改变分桶方式。主体标识应通过请求中的 `subject_key` 提供，或在实验配置中设置 `bucket_key`。

## 生效时间

部署和路由均可设置生效开始时间 `effective_from` 与生效结束时间 `effective_to`：

| 字段             | 生效条件                              | 未设置时       |
|------------------|---------------------------------------|----------------|
| `effective_from` | `effective_from <= now`，包含开始时间 | 无开始时间限制 |
| `effective_to`   | `now < effective_to`，不包含结束时间  | 无结束时间限制 |

同时设置开始和结束时间时，结束时间必须晚于开始时间。路由及其绑定部署均处于生效期内，路由才可参与流量分配。

例如，将路由的生效范围设为北京时间 2026 年 10 月 1 日零时至 11 月 1 日零时：

```bash
datamind route update <routing_id> \
  --effective-from '2026-10-01T00:00:00+08:00' \
  --effective-to '2026-11-01T00:00:00+08:00'
```

该路由从北京时间 2026 年 10 月 1 日零时开始生效，到同年 11 月 1 日零时失效，不包含结束时刻。

> **注意**
>
> 时间统一转换为 UTC。CLI 按默认时区解析未带时区的时间，并使用该时区显示时间。
>
> 默认时区为 `Asia/Shanghai`，可通过 `.env` 中的 `DATAMIND_TIMEZONE` 设置。跨时区配置时，建议显式指定时区偏移。
>
> 更新路由时，未提供 `--effective-from` 或 `--effective-to` 的时间设置保持不变。
