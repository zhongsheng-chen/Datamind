# 文档维护

Datamind 的文档源码位于 `docs/`，由 MkDocs 构建为网站。本页介绍如何新增和修改页面、同步代码生成的参考内容，以及在提交前验证文档。

## 本地预览

在项目根目录运行以下命令，安装文档构建所需的依赖：

```bash
python -m pip install -r docs/requirements.txt
```

安装完成后，启动本地预览：

```bash
python -m mkdocs serve
```

在浏览器中打开终端显示的地址。预览服务会监听文件变化，保存修改后自动刷新页面。

## 新增和调整页面

新增内容前，先检查是否可以补充到已有页面。需要单独成页时，根据内容用途选择栏目：

| 内容用途             | 所属栏目 | 写作重点                     |
|----------------------|----------|------------------------------|
| 第一次安装并完成调用 | 快速入门 | 用最少步骤得到可验证的结果   |
| 从头实践一个完整场景 | 教程     | 连续步骤、阶段检查和最终结果 |
| 完成一项具体工作     | 操作指南 | 前提、操作方法和失败处理     |
| 理解系统如何工作     | 核心概念 | 资源关系、行为规则和设计取舍 |
| 查询命令、参数与用法 | 命令行   | 命令语法、参数、默认值与权限 |
| 查询字段、配置或取值 | 参考手册 | 准确且便于检索的定义         |
| 部署和维护服务       | 运维     | 依赖、进程、监控、升级与恢复 |
| 修改和交付代码       | 开发     | 开发环境、扩展、测试和发布   |

- **新增页面**：在 `docs/` 下创建 Markdown 文件，并在 `mkdocs.yml` 中配置导航。导航名称与页面标题保持一致。
- **引用内容**：命令和参数定义维护在命令行文档中，字段定义维护在参考手册中，教程和指南通过链接引用。
- **移动页面**：更新导航和相关链接；需要保留旧地址时，在 `mkdocs.yml` 中配置重定向。

## 正文和示例

页面开头简要说明用途和前提，正文按读者的阅读或操作顺序展开。

- **内容结构**：操作说明按步骤组织，概念说明突出资源关系，参考内容便于查找定义。
- **操作结果**：给出预期结果和排错入口。异步任务需分别说明如何确认提交成功和处理完成。
- **示例内容**：模型名、版本和路径保持一致，需要替换的值应注明含义。
- **术语表达**：正文使用中文，命令、参数和字段保留原名。必要时在术语首次出现处标注代码名。
- **图片和链接**：截图存放于 `docs/assets/images/`，随操作流程一起更新；页面和资源使用相对链接。

## 更新参考文档

以下参考页面由代码生成，修改时应更新来源文件，再重新生成：

| 生成页面                                  | 主要来源                             |
|-------------------------------------------|--------------------------------------|
| `docs/cli/` 下的命令索引和命令组页面      | Typer 命令定义及命令函数文档字符串   |
| `docs/reference/environment-variables.md` | Pydantic Settings 配置定义及字段说明 |
| `docs/reference/runtime-schemas.md`       | Runtime 请求模型及字段说明           |

- **命令说明**：维护在命令函数的文档字符串中，使用独立一行的“输出：”标记输出说明。
- **字段说明**：配置字段优先使用 `Field.description`，也支持类或模块文档字符串；请求字段使用 `Field.description`。
- **页面模板**：维护在 `doc_support/templates/`，请求模型的业务条件位于其中的 `runtime-conditions/`。
- **分组和示例**：命令分组、指南链接、API 示例及配置单位维护在 `doc_support/metadata.json`。

安装[项目依赖](index.md#安装依赖)后，在项目根目录运行：

```bash
python -m scripts.generate_docs_reference
```

检查生成差异，并将来源文件和生成页面一起提交。生成失败时，根据错误提示补充说明或修正示例后重试。

## 验证与发布

预览修改的页面并验证命令示例后，在项目根目录检查参考文档是否与源码一致：

```bash
python -m scripts.generate_docs_reference --check
```

若提示 `Reference drift`，重新生成参考文档后再检查。通过后，执行严格构建：

```bash
python -m mkdocs build --strict
```

构建通过后，将文档和来源文件一起提交。ReadTheDocs 使用 `.readthedocs.yaml` 构建发布，完成后检查线上页面。
