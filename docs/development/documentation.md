# 文档维护

术语首次出现使用中文与代码对象，例如部署（`Deployment`），后续正文优先使用中文。命令、参数与字段保留代码拼写。

产品文档统一维护在 `docs/`，通过 MkDocs 构建并发布到 ReadTheDocs。组件 README 保留本地开发说明，使用流程和参考内容在本站维护。

## 页面组织

文档按读者意图组织，文件目录只承担源码归类，不要求与导航栏目机械对应：

| 栏目 | 回答的问题 | 内容要求 |
| --- | --- | --- |
| 快速入门 | 如何尽快完成第一次可用调用？ | 最短安装、初始化和首个模型服务链路 |
| 教程 | 如何从头完成一个完整场景？ | 明确前置条件、连续步骤、检查点和结束状态 |
| 操作指南 | 如何完成某项具体工作？ | 面向任务给出操作顺序、必要约束和故障入口 |
| 核心概念 | 为什么这样工作？ | 解释资源作用、关系、决策规则和生命周期 |
| 参考手册 | 精确的命令、字段和取值是什么？ | 以代码定义为准，完整、稳定、便于检索 |
| 运维 | 如何部署、观察和恢复服务？ | 进程、依赖、容量、升级、备份和排错 |
| 开发 | 如何修改、测试和发布项目？ | 代码结构、扩展边界、测试与交付流程 |

同一事实只设一个权威页面。例如 CLI 参数属于参考手册，教程只展示完成场景所需的参数；流量决策算法属于核心概念，金丝雀指南只说明如何安全调整比例。其他页面用链接引用，避免复制参数表和状态规则。

目录标题使用简短、具体的主题名，如“模型管理”“影子发布”“环境变量”。同级目录保持相同粒度，导航名称与页面标题一致，产品概览除外。操作动词用于页内步骤，参数与代码对象保留原名。

新增页面时先确定读者要完成的任务，再选择所属章节。教程和指南按操作顺序组织，说明准备条件、需要替换的占位符、关键命令、预期结果和必要的失败处理。概念页不堆叠操作命令，参考页不承担完整教学流程。跨页内容使用链接衔接，避免重复维护同一段参数或规则。

## 写作要求

页面开头说明主题、适用场景和必要前提。正文围绕本页职责展开，资源关系由概念页解释，操作步骤由指南说明，精确字段由参考页维护。

- 标题使用具体主题或操作名称，避免把页面内容逐项拼接到标题中。
- 概念页用定义、关系和行为说明建立理解，操作命令链接到指南。
- 指南提供完成任务所需的最小示例，首次注册不要求提前准备更新和修正文件。
- 示例中的模型名称、版本和文件路径保持一致，明确必要的占位符与条件分支。
- 说明操作结果、异步完成条件和失败处理，区分系统约束与发布建议。
- 使用当前实现支持的能力描述，省略一次性运行数据和开发阶段的临时结论。

## 更新参考内容

以下参考页面由代码定义生成，不直接编辑：`docs/cli/` 下的命令索引和命令组页面、`reference/environment-variables.md`、`reference/runtime-schemas.md`。来源分别是 Typer 命令、Pydantic Settings 和 Runtime 请求模型。

生成与检查命令：

```bash
python -m scripts.generate_docs_reference
python -m scripts.generate_docs_reference --check
```

生成器只读取定义，不读取本机凭据。配置说明优先读取 `Field.description`，其次读取类与模块文档字符串中的字段或环境变量说明；生成器元数据补充单位。新增配置缺少说明时生成失败，避免产生空白说明列。页面正文和 Markdown 布局维护在 `doc_support/templates/*.md.tpl`，使用标准库 `string.Template` 的 `${name}` 占位符；API 示例、业务条件、配置单位和分组标题维护在 `doc_support/metadata.json`。调整生成页面的说明文字时，修改对应模板或元数据，然后重新生成。生成器负责读取源码定义、校验示例和填充模板，缺少模板占位符时立即失败。

## 预览与验证

```bash
python -m pip install -r docs/requirements.txt
python -m mkdocs serve
```

在浏览器中检查导航、代码块、表格和图片。提交前执行严格构建：

```bash
python -m mkdocs build --strict
```

缺失页面、内部链接和锚点问题会使构建失败。命令与业务约束还需要对应测试或实际运行验证。

## 截图与发布

截图放在 `docs/assets/images/`，使用稳定文件名并在正文说明操作与预期结果。可下载的示例配置放在 `docs/assets/configs/`，在正文提供下载链接和使用命令。更新场景时一起检查模型名、版本、数据和相关截图，避免页面内容与界面不一致。

ReadTheDocs 使用 `.readthedocs.yaml` 构建。更新已启用版本的分支后可重新构建，也可在项目后台手动触发。预览版本确认后再更新正式版本。
