# 文档维护

术语首次出现使用中文与代码对象，例如部署（`Deployment`），后续正文优先使用中文。命令、参数与字段保留代码拼写。

产品文档统一维护在 `docs/`，通过 MkDocs 构建并发布到 ReadTheDocs。组件 README 保留本地开发说明，使用流程和参考内容在本站维护。

## 页面组织

快速开始与进阶教程提供可跟随的学习路径，使用指南围绕具体任务展开，核心概念解释资源关系与运行机制，运维部署说明进程、基础设施与故障处理。CLI、配置和 API 的参数集中放在 Reference，开发章节介绍扩展、测试与发布。

新增页面时先确定读者要完成的任务，再选择所属章节。指南按操作顺序组织，说明准备条件、命令、预期结果和必要限制。跨页内容使用链接衔接，避免重复维护同一段参数或规则。

## 更新参考内容

CLI 参数、配置默认值和预测服务（`Runtime`）请求字段从代码定义生成：

```bash
python -m scripts.generate_docs_reference
python -m scripts.generate_docs_reference --check
```

生成器只读取定义，不读取本机凭据。配置说明优先读取 `Field.description`，其次读取类与模块文档字符串中的字段或环境变量说明；生成器元数据补充单位。新增配置缺少说明时生成失败，避免产生空白说明列。调整生成页面的说明文字时，同时修改生成器，避免下次生成覆盖编辑结果。

## 预览与验证

```bash
python -m pip install -r docs/requirements.txt
python -m mkdocs serve
```

在浏览器中检查导航、代码块、表格和图片。提交前执行严格构建：

```bash
python -m mkdocs build --strict
```

缺失页面、内部链接和锚点问题会使构建失败。命令与业务约束还需要对应测试或实际运行验证。

## 截图与发布

截图直接放在 `docs/assets/`，使用稳定文件名并在正文说明操作与预期结果。更新场景时一起检查模型名、版本、数据和相关截图，避免页面内容与界面不一致。

ReadTheDocs 使用 `.readthedocs.yaml` 构建。更新已启用版本的分支后可重新构建，也可在项目后台手动触发。预览版本确认后再更新正式版本。
