# 模型兼容性

注册模型前，请确认框架、模型类型和文件格式符合以下要求，并在运行环境中安装相应依赖。

## 框架、模型类型与文件格式

| 框架     | 模型类型                   | 文件格式                     |
|----------|----------------------------|------------------------------|
| sklearn  | 逻辑回归、决策树、随机森林 | `.pkl`、`.pickle`、`.joblib` |
| xgboost  | XGBoost                    | `.json`、`.ubj`、`.model`    |
| lightgbm | LightGBM                   | `.txt`、`.model`             |
| catboost | CatBoost                   | `.cbm`                       |

> **提示**
>
> 注册时，平台会先检查文件后缀，再加载模型文件。加载过程中会读取特征名称及顺序，校验模型与指定的框架、模型类型和任务类型是否匹配。

## 评分与分类

- **评分任务**：使用以 `LogisticRegression` 为估计器的 `optbinning.Scorecard`。注册时指定框架 `sklearn`、模型类型 `logistic_regression` 和任务类型 `scoring`。
- **分类任务**：支持上述框架的二分类模型。注册时指定对应的框架和模型类型，任务类型设为 `classification`。

分类概率表示属于正类的概率。使用 scikit-learn 或 CatBoost 训练的模型，以 `classes_` 中的第二个类别为正类；XGBoost 和 LightGBM 的原生 Booster 使用 0/1 标签训练时，以 `1` 为正类。

请求示例与响应说明见[评分与分类](../guides/scoring-and-classification.md)。

## 输入特征

注册时，平台读取模型的特征名称及顺序，生成输入 Schema。

| 模型              | 特征名称来源                      |
|-------------------|-----------------------------------|
| scikit-learn 模型 | `feature_names_in_`               |
| 评分卡模型        | `binning_process_.variable_names` |
| XGBoost 模型      | `feature_names`                   |
| LightGBM 模型     | `feature_name()`                  |
| CatBoost 模型     | `feature_names_`                  |

> **提示**
>
> 训练数据应包含列名，模型保存并重新加载后应保留特征名称。注册后，请检查输入 Schema，确认预测请求的字段名称和类型符合模型要求。若无法提取特征名称，请检查训练数据及模型保存方式。

## 保存模型

训练完成后，按模型框架选择保存方式：

| 模型                          | 保存方式                                                                       |
|-------------------------------|--------------------------------------------------------------------------------|
| scikit-learn 模型、评分卡模型 | 使用 `joblib.dump` 保存                                                        |
| XGBoost 模型                  | 使用 `save_model` 保存                                                         |
| LightGBM 模型                 | 使用 `save_model`（原生接口）或 `booster_.save_model`（scikit-learn 接口）保存 |
| CatBoost 模型                 | 使用 `save_model` 保存                                                         |

> **提示**
>
> 文件后缀须与实际保存格式匹配。XGBoost 和 LightGBM 模型须使用框架原生格式保存。

了解如何训练和保存模型，请参阅[模型训练示例](../examples/index.md)。

## 依赖与兼容验证

请保持训练与运行环境的依赖版本兼容，并在部署前验证模型能否正常加载和预测。

| 依赖         | 版本要求     |
|--------------|--------------|
| scikit-learn | `>=1.6`      |
| XGBoost      | `>=2.0`      |
| LightGBM     | `>=4.0`      |
| CatBoost     | `>=1.2`      |
| optbinning   | `>=1.0,<2.0` |

上述版本要求用于安装依赖，模型能否正常运行仍需验证。具体要求以 `pyproject.toml` 为准。

## 常见问题

- **模型文件无法加载**：检查文件后缀是否受支持，保存方式是否正确，以及对应框架依赖是否已安装。
- **模型类型不匹配**：核对注册时指定的框架、模型类型和任务类型。
- **评分任务使用普通分类器**：确认保存的是完整的 `optbinning.Scorecard` 对象。
- **输入特征不匹配**：核对训练数据列名、注册后的输入 Schema 和预测请求中的字段。

模型加载失败时，请检查运行实例的错误信息和预测服务日志。
