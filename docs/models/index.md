# 模型与版本

训练完成后，将模型文件注册到平台。模型保存名称与任务类型，版本标识一次业务交付，制品记录对应文件及修订。

## 准备制品

注册前确认框架、算法和任务类型匹配，并安装对应依赖。支持的格式见[兼容性](compatibility.md)，训练入口见[示例](../examples/index.md)。

| 项目 | 要求 |
| --- | --- |
| 模型名 | 小写字母、数字、点、下划线或连字符，以字母或数字开头和结尾 |
| 业务版本 | 主版本.次版本.修订版本，例如 1.0.0 |
| 任务类型 | classification 或 scoring |
| 制品文件 | 已训练、可加载，并保留所需特征信息 |

## 注册与激活

`datamind model register` 保存制品及版本信息，`datamind model activate` 激活模型或指定版本。激活后，继续创建部署并接入流量。完整命令见[快速上手](../getting-started/quickstart.md)。

模型的 framework、model_type 和 task_type 在创建后固定。注册新版本时沿用这些信息，算法或任务发生变化时使用新的模型身份。

## 更新制品

第一次注册创建 revision 1。同版本、同摘要的文件再次提交时，返回已有记录，修订号保持不变。

同版本文件发生变化时，使用 `--force` 创建新修订，需要同时满足：

- 版本处于 inactive。
- 版本未删除。
- 该版本从未有过部署记录，包括已删除的部署。

已上线版本通过新业务版本交付，便于回滚和追踪。替换制品后，旧修订保留在历史记录中，当前版本指向新修订。

## 停用与弃用

暂时下线使用 deactivate，之后可以重新 activate。deprecate 表示弃用，之后仅可归档。archived 为终态。

版本级操作使用 `--version` 或 `--version-id`。省略版本时会操作模型及关联版本，执行前用 show 确认范围。归档由 Console 或服务管理，model CLI 未提供 archive 命令。

## 删除与恢复

逻辑 delete 标记资源已删除，保留记录与制品。restore 恢复删除标记，关联模型与制品需仍可恢复，资源随后按原有生命周期状态管理。

purge 用于永久清理已逻辑删除目标的物理制品，执行前检查有效部署与仍在运行的节点，并记录清理结果。清理失败可根据存储和引用状态排查，已清理制品无法通过 restore 找回。

## 下线顺序

1. 结束相关实验流量，处理分组引用。
2. 禁用并删除路由。
3. 停用部署，等待节点卸载，再删除部署。
4. 停用并删除版本或模型。

历史请求、执行和审计记录保留用于追踪。界面操作见[Console 手册](../guides/console.md)，全部参数见[模型 CLI](../cli/model.md)，合法转换见[状态与权限](../reference/states-permissions.md)。
