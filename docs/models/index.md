# 模型与版本

模型注册将已训练的制品交付给平台，训练过程由调用方完成。Model 描述模型身份，Version 描述业务版本，Artifact 记录具体制品修订。

## 注册前准备

确认框架、算法与任务类型匹配，并安装对应 extra。模型名使用小写字母、数字、点、下划线或连字符，以字母或数字开头和结尾；版本使用主版本.次版本.修订版本，例如 1.0.0。文件格式见[兼容性与制品](compatibility.md)，可运行的训练入口见[示例](../examples/index.md)。

## 注册与激活

`datamind model register` 注册制品，`datamind model activate` 激活模型或指定版本。注册和激活后，还需创建 Deployment 才能进入服务交付流程。

第一次操作可直接参考[快速上手](../getting-started/quickstart.md)。命令、参数和默认值归入[CLI Reference](../cli/index.md)。

## 制品修订与生命周期

首次提交创建版本及 revision 1 制品；后续提交由注册服务校验已有版本与制品摘要。版本的当前制品与历史修订分别记录。

相同版本、相同制品摘要的重复注册按幂等成功返回，不创建新的修订。文件改变时必须使用 `--force`，并满足版本 inactive、未删除、从未有部署记录；即使旧部署已删除也不能用 force 替换曾部署的版本。已上线模型应注册新业务版本，从而保留可追溯性。模型身份的 framework、model_type 和 task_type 不能通过重复注册变更。

## 停用、弃用与删除

`deactivate` 用于暂时下线，之后可以再次 activate；`deprecate` 表示弃用，不能重新激活，只能进一步归档。归档是终态，当前 model CLI 没有 archive 命令，Console 与服务提供对应管理能力。版本级操作使用 `--version` 或 `--version-id`；省略版本会作用于模型及关联版本，执行前用 show 确认范围。

逻辑 delete 标记删除但保留记录与制品；restore 恢复删除标记，需要关联模型和制品仍可恢复，不会绕过当前生命周期状态。purge 只适用于已逻辑删除的目标，并检查有效部署和仍在运行的节点；它清理物理制品并记录成功或失败状态，永久清理后不能承诺恢复。

下线顺序为禁用并删除相关路由、停用部署、等待运行节点卸载、删除部署，再停用和删除版本或模型。运行中的实验分组等引用也必须先处理。历史请求、执行和审计作为追踪信息保留。演示流程见[Console 删除与回收站](../guides/console.md)，逐命令选项见[模型 CLI](../cli/model.md)，合法状态转换见[状态与权限](../reference/states-permissions.md)。
