# 部署与运行

部署（`Deployment`）将一个模型版本发布到指定环境，记录发布方式、角色与期望状态。运行实例（`Runtime`）记录该部署在各预测服务 Worker 中的实际加载状态。两者共同描述一次发布：部署定义预期运行的模型版本，运行实例反映实际加载结果。

## 从注册到预测

从注册模型到提供预测服务，通常包括以下步骤：

1. **注册模型**：保存模型文件和版本信息。
2. **激活版本**：使该版本可用于创建部署。
3. **创建部署**：指定模型版本、运行环境、发布方式和角色。
4. **启用部署**：将部署设为启用状态，预测服务开始协调模型加载。
5. **确认加载**：检查对应运行实例的状态是否为 `running`，确认模型已加载。
6. **配置路由**：设置请求匹配规则和流量比例，将流量分配到部署。
7. **发起请求**：调用预测接口，验证返回结果及使用的模型版本。

> **提示**
>
> 接入流量前，请确认部署已启用，且对应运行实例的状态为 `running`。状态说明见[状态与权限](../reference/states-permissions.md)，路由配置见[流量分配](../routing/index.md)。

下线时，先停用相关路由，再停用部署。等待模型卸载完成后，删除部署并清理不再使用的版本及模型文件。

## 发布方式与角色

| 发布方式                | 用途                                                                     | 发布类型 | 角色                                             |
|-------------------------|--------------------------------------------------------------------------|----------|--------------------------------------------------|
| [全量发布](full.md)     | 一次性将全部预测流量切换至新版本                                         | `full`   | 自动设为 `champion`                              |
| [金丝雀发布](canary.md) | 先以少量预测流量验证候选版本，验证通过后逐步扩大其流量比例               | `canary` | 主部署使用 `champion`，候选部署使用 `challenger` |
| [影子发布](shadow.md)   | 复制预测请求给候选版本，仍返回主预测结果，影子预测结果仅记录供比较和分析 | `shadow` | 自动设为 `shadow`                                |

部署角色用于区分主版本、候选版本和影子版本，流量比例由路由配置。启用部署后，还需配置相应路由才能按设定比例分配流量。影子路由独立采样，不参与普通路由的流量分配。详见[流量分配](../routing/index.md)。
